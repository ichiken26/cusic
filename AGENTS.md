# cusic agent instructions

cusic is a local-first music editing CLI, not an autonomous Cubase GUI driver.
Do not write the SQLite project database directly; use cusic commands.

1. First run `cusic status` and `cusic track list`. Inspect the target with `cusic inspect --track TRACK --bars START:END`. Track absolute onsets use 480 PPQ.
2. For a precise edit, construct a validated patch JSON with `baseRevision` equal to current HEAD, one track and an inclusive bar range. `cusic patch apply FILE.json` **replaces the whole range**, so include retained notes too. Changes crossing range boundaries fail safely.
3. Validate with `cusic diff REV` and `cusic validate`. Use `cusic revert REV` only if the revision is HEAD. Never blindly replay failed patch operations.
4. Treat Cubase and vocal synthesis as sources of human edits. **No live two-way synchronization exists.** Use `cusic sync plan --from file.dawproject` first. Only after reviewing the plan, use `cusic sync pull --from file.dawproject --base-revision N`. Vocal tracks are intentionally skipped to preserve their lyrics and tuning.
5. For TuxGuitar use `cusic import score.tg` only with TuxGuitar 2.x ZIP/XML. For TuxGuitar 1.x request exported MIDI. Do not claim TAB technique or pitch-bend retention.
6. For Suno, prefer already exported isolated WAVs/MIDI. New audio-first songs may use `cusic init --name SONG` with no BPM (tempo=0 means pending), followed by `cusic suno import ./stems`. Analyze `cusic tempo analyze`, discuss half/double-time uncertainty with the user, then confirm via `cusic tempo set --bpm N`. Only use `tempo render --out NEW_DIR --confirm` after explicit approval; default uniform stretch, adaptive is experimental and may misalign beats.  `cusic suno import ./stems` stores WAV as immutable assets. Optional `cusic suno separate` and `cusic suno transcribe` invoke installed Demucs / Basic Pitch. Transcription is approximate. Do not claim audio-to-perfect-score conversion.
7. For Miku V4X use `vocal_voices` to discover ACTUAL voice references from VSQX files in the song folder. Never guess voicebank CompIDs. Call `vocal_notes_apply` with `createTrack=true` to create SideVocal and add many note+lyric entries safely in one revision, then `score_export` with `format="vsqx"` and `track="SideVocal"`; `template` is OPTIONAL and cusic discovers existing VSQX automatically. Prefer a genuine Original bank; when only Solid/Sweet are available, export under a REAL available voice with a conspicuous fallback warning, not a fake Original. Japanese "っ" (silence), "br1".."br5" breath lyrics and "-" sustain are recognized; listen to the actual V4X output because breath samples vary. Existing edited singers still use `vocal_vsqx_edit_existing` to preserve native tuning.
8. For Teto SV2 prefer the automatic SVP workflow: run `vocal_phonology_analyze` to detect mora-boundary risks, /i,u/ vowel devoicing and consonant preutterance, then `svp_clone_plan`, and after approval `svp_clone_apply` (or `cusic svp apply --from original.svp --track Teto --out NEW.svp`). cusic clones the Teto track, applies new notes on the CLONE, and mutes the original only in the new SVP. No manual JSON→JS→SynthV script step is needed. Do not force a full vowel in phrase-final す or mis-devoice く before ゆ. When several kana morae share one new note, distribute them within its original bounds; never place earlier notes before a barline. Original SVP/retakes/curves are preserved, but new note rendering must be checked inside SynthV 2 Pro. Legacy TypeScript/Zod script remains an optional path.
9. Export to fresh output files (MIDI, VSQX, DAWproject, SynthV); never modify a source `.cpr`, source audio or vocal project without consent and backups. Never claim that DAWproject or Piapro Studio import was validated on the user's machine.
10. SQLite holds revisions, not Git. Back up the DB with SQLite-safe backup tools, including WAL data.

Example musical patch: `examples/patch.json`.

## Agent-first workflow

Read `docs/agent-first.md` for project-scoped MCP setup and safe vocal/mix workflows. Use the MCP tools from `cusic mcp` rather than expecting users to know the CLI.
For an existing mixed song, use the **original Cubase-exported DAWproject** as the source of `mix_plan` / `mix_apply`, not an inferred session built only from note/WAV data. `project_import` and `cusic setup` now store the entire original DAWproject, including VST3 states, routing and automation, to retain these on `score_export` / `cusic export --format dawproject`. An unchanged note arrangement produces a byte-identical DAWproject copy; simple single-clip note edits preserve all other archive assets. More complex note edits fail rather than discard effects. For projects imported by older cusic versions use `project_source_attach` (or `cusic source attach --from original.dawproject`) after checking that score notes and tempo match. Never silently regenerate a Cubase session from flattened notes/WAV when a source archive is known.
Use `effects_inspect` to read VST/insert/parameter metadata, `kontakt_diagnose` to report observable channel/output configuration, `effects_plan` to validate generic compressor inserts, VST3 cloning or explicit state operations, and `effects_apply` only after user approval. Never claim to decode Kontakt's proprietary routing or freely rewrite opaque VST3 preset bytes; unknown plugin parameters require state created by the same plugin. Always ask approval before `mix_apply`; it creates a NEW .dawproject file. Never overwrite .cpr, source recordings, .svp, .vsqx or .ppsf.
Backup vocal source with `vocal_backup_source`. For NEW or cusic-managed vocals, prefer `vocal_notes_apply` (atomic explicit additions / ID-based updates; no bar-wide replacement), then `score_export format=vsqx` with automatic real-voice discovery. Do NOT use generic `patch_apply` for vocals; it is intentionally still blocked because it erases entire bars. For existing expressive VSQX use `vocal_vsqx_edit_existing` and the original source. For Teto prefer `vocal_phonology_analyze` → `svp_clone_plan` → `svp_clone_apply`, which retains all original tuned notes in a muted source track. The TypeScript/Zod `synthv/src/safe.ts` remains for precise in-editor updates. NEVER destructively re-create tuned vocal content in the source file.

## NumPy/SciPy spectral worker
Prefer the read-only MCP mix_analyze_spectral tool for quantitative frequency-domain mixing research. It uses NumPy rFFT and SciPy WAV input. When Python dependencies are missing, report the installation command (py -m pip install -r audio/requirements.txt) and fall back to mix_analyze_stems for Go-only approximate statistics. The sampled FFT results are not integrated LUFS, true peak or definitive auditory masking. Never alter the recording during analysis.
